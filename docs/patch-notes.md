# 模型补丁的 hunk 头

2026-10-22。M5 D 的试跑（PR #36）里，Claude Opus 5.5 的 5 个补丁只有 1 个过了 `git.apply_check`，另外 4 个的 hunk 头数字不对，任务都以 `patch rejected` 结束，修得对的补丁也开不出 PR。这次改成：agentd 读补丁时按 hunk 的行重写 hunk 头（行数，以及从哪一行开始），之后照旧严格检查。

## 试跑的 4 个补丁错在哪

从试跑的账本（`~/.cache/agentos-eval/state/pilot`）取出补丁，对着各自的提交看：

| 用例 | hunk | 头写的 | 按行算 | 错在哪 |
|---|---|---|---|---|
| go-vouch-cookie-parts | 1 | `-98,17 +98,23` | `-98,15 +98,24` | 行数 |
| py-fsspec-jinja-refs | 1 | `-115,15 +115,16` | `-115,14 +115,15` | 行数 |
| | 2 | `-135,7 +136,7` | `-134,7 +135,7` | 位置差 1 |
| | 3 | `-146,10 +147,10` | `-145,9 +146,9` | 行数，位置差 1 |
| go-argocd-proxycommand-inj | 1 | `-311,6 +311,9` | `-311,7 +311,10` | 行数（少数一行） |
| | 2 | `-328,4 +331,14` | `-327,4 +330,13` | 行数，位置差 1 |
| java-jenkins-replay-scripts-inj | 1 | `-373,6 +373,7` | `-376,5 +376,6` | 行数，位置差 3 |

- 拒绝来自 agentd 自己的 Go 检查（go-gitdiff 解析失败），每次 0.3 毫秒，没走到沙箱里的 git。交接记录里的 `corrupt patch at line N` 是 git 的说法，原因相同。
- `git apply --check --recount` 能接受这 4 个，不只是因为重算了行数：git 还会在文件里上下找 hunk 的位置（offset），3 个补丁的起始行号错了 1–3 行，git 都找到了。go-gitdiff 只按头写的行号打。
- 所以任务说明列的两种做法都不够：只重算行数，4 个里只救回 go-vouch 一个。

顺带发现两个今天就有的问题，两道检查都放行，但 PR 的内容和补丁的文字对不上：

1. **行数写少了，多出来的行被悄悄丢掉**。头的行数数完之后还有 hunk 的行（`+` 行、上下文），git 和 go-gitdiff 都当作补丁外面的杂行忽略。审批人在卡片上看得到这些行，PR 里却没有。审批人手改补丁时最容易这样：加了一行、头没改，PR 会丢掉最后一行（黑盒测试里那次修改就是，丢掉的是新的 `return`）。
2. **没有上下文的插入**（`@@ -5,0 +6 @@`，`diff -U0` 的写法）：go-gitdiff 插在第 5 行之前，git 插在文件末尾，两道检查都说打得上，PR 用的是 go-gitdiff 的结果，比补丁说的早一行。

## 选了哪种做法，为什么

1. **两边都用 `git apply --recount`**：git 的 `--recount` 只重算行数，位置靠它自己的就近查找。Go 这边要和它一致，得照搬 git 的 recount 和就近查找（`match_beginning`、`match_end`、空白的规则），两份实现必须逐字节一致；而且同样的几行在文件里出现两次时，git 悄悄挑离头写的行号近的那一处。不选。
2. **按 hunk 的行重写行数，存成新的 blob，之后严格检查**（任务说明的第二种）：方向对，但只改行数不够，见上。
3. **选的**：第二种加上位置，在 agentd 读补丁的地方做，只有一份实现（`internal/patch`）。
   - 行数取自 hunk 的行，头写的行数不用。
   - 位置：hunk 的旧行（上下文和删掉的行）在头说的那一行开始、逐字相同，就留在那里；不在，就找文件里恰好一处有这些行的地方；一处都没有、或者不止一处，拒绝。不做模糊匹配，每一行都要逐字相同。
   - 只改 hunk 头那一行（头后面的函数名等原样保留），补丁别的字节都不动。头写对了的补丁一个字节不变。
   - 之后照旧严格检查：go-gitdiff 按改好的头精确地打，沙箱里的 `git apply --check` 不加 `--recount`，检查的是改好的补丁。
   - 审批卡片显示改好的补丁（就是 PR 的文件内容），另列 `patch_rewritten`：哪个文件的第几个 hunk，原来的头和改后的头；还有一条说明。载荷和它的哈希照旧绑定审批，不受影响。
   - `git.apply_check` 的结果多一个 `rewritten_hunks`（改了几个头，只在有改动时出现），工作流不用它。

**为什么不另存一份 blob、让工作流把它传给 open_draft_pr**：

- 改好的补丁是“补丁 + 提交”的纯函数，同样的输入每次得出同样的字节。apply_check、open_draft_pr 的 Prepare、审批卡片三处各算一次，结果一样，不需要存。
- 要让工作流传新的 ref，得改工作流：在途的任务重放时要靠 `.get(..., 原来的 ref)` 才不变，T10 的版本测试也要跟着看；审批卡片上“这个补丁是不是这次审计提出的”（`tasks.auditFindings` 按 patch_ref 比对）也要另外对应。
- 被攻破的工作流本来就可以跳过 apply_check，open_draft_pr 不能只信 apply_check 的结果，还得自己再读一遍。现在两处用的是同一段代码。
- 审批人看到的改好的补丁本来就记下了：出审批单时，Describe 的输出存成 blob（审批单的 context）。模型原样写的补丁在 report_ref 和 model_calls 的答复里。

## 规则

- **hunk 的行**：从 hunk 头往下，以空格、`-`、`+` 开头的行，空行（git 和 go-gitdiff 都把空行当作空的上下文行），和 `\ No newline at end of file`；到下一个 hunk 头、下一个文件的头（`diff ` 开头的行，或者 `--- `、`+++ ` 后面紧跟 `@@ -`，和 git、go-gitdiff 认文件头的规则一样）、format-patch 的签名或者结尾为止。
- **hunk 末尾的空行**：后面紧跟同一个文件的下一个 hunk 时算作空的上下文行（不然 git 和 go-gitdiff 都会把下一个 hunk 当作没有文件头）；后面是别的文件、补丁后面的文字或结尾时不算，留在原处（两边都当作杂行忽略）。
- **hunk 之后、不属于任何 hunk 的行**：必须开始下一个文件，或者是补丁后面的文字，直到结尾都没有像 hunk 的行（也可以是 format-patch 的签名：`-- ` 加上后面的版本号）。别的一律拒绝：这样的行有两种读法。
- **最后一行**：是 hunk 的行又没有换行，补上换行。git 拒绝没有换行的 hunk 行；go-gitdiff 会读成“文件末尾没有换行”。
- **位置**：见上。新的一边从哪一行开始，按文件里的先后，由旧的一边加上它前面的 hunk 增减的行数算出（和 git 的写法一致，数为 1 时省略）。
- **没有旧行的 hunk**（没有上下文，也不删行）：只能给空文件或新文件写第一批行，其他一律拒绝：没有什么能说明它该放哪，今天 go-gitdiff 和 git 放的位置也不一样（上面第 2 条）。
- **上限**：一个补丁最多挪 32 个 hunk（`MaxMoved`），每挪一个要扫一遍文件。找位置用 KMP，文件的每一行最多比两次，同一行重复一百万次的文件也不会变慢；找到第二处就停。改好的补丁也不能超过 256 KiB。
- **自查**：改完之后，go-gitdiff 重新解析改好的补丁，每个文件、每个 hunk 的位置、行数、每一行都要和实际打上去的一样，否则拒绝。
- **审批人的修改**也按这套规则读：手改的补丁头不用数对。

## 行为变化

现在拒绝、以前放行的：

- hunk 之后夹着文字，后面又有 hunk 或文件（以前文字之后的 hunk 行被忽略，或者被拒绝）。
- 非空文件里没有上下文的插入（上面第 2 条）。
- 头的行数数完之后紧跟像 hunk 的杂行：现在算进 hunk，通常就打不上了。
- `-- x`、`++ y` 这样的删除和增加正好在两个 hunk 的交界、看上去像文件头，头的行数又把它们算在 hunk 里：现在读成文件头，会被拒。很少见。

现在放行、以前拒绝的：行数、位置写错，但每一行都在文件里、而且位置唯一的补丁。

## 结果

- 试跑的 5 个补丁现在都打得上（indico 那个本来就对，一个字节没变）。改好的补丁用 `git apply --check`（不加 `--recount`）检查也都通过，没有 offset。和模型的补丁相比，只有 hunk 头那几行变了。

## 留到后面

- **让模型不写行号**：模型数不清行号，这次是在 agentd 这边兜底。更根本的做法是改补丁的格式，让模型给“把这几行换成那几行”（搜索、替换块），行号由 agentd 算，补丁也由 agentd 生成。要改提示词和输出 schema，评测的版本也跟着变，另做。
- **git 的检查只说打不打得上**：`git apply --check` 不和 Go 打出来的结果比对，PR 用的是 Go 的结果。现在位置都对上了，git 第一次就会在同一处找到；要做成硬检查，可以在沙箱里 `git apply --cached` 到临时索引，再比对 blob ID（要给服务器一个临时的对象目录）。
- 改好补丁时补上的最后换行不算“改写”，`patch_rewritten` 不列；载荷里看得到。
