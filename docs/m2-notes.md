# M2 记录：模型网关与预算

M2 拆成三段（设计文档第 12 节）：M2a 预算、M2b Claude 适配器、M3 之后的 M2c OpenAI 兼容适配器。

## M2a：预算（2026-10-17）

验收 T7 通过。供应商仍是假的，预算逻辑本身和供应商无关。

### 做了什么

- **价格表** `config/prices.yaml`（`internal/pricing`）：带版本号，单位是美元每百万 token，也就是每 token 多少 micro 美元。内部按千分之一 micro 存成整数，$0.20 这样的价格也是精确值；所有取整一律向上。没填价格（null）的模型调用不了；agentd 启动时检查每个任务可能用到的模型（含回退）都有价格。
- **上限**：输入 token（供应商的计数方法）加 10%，乘以所有候选模型里最高的输入单价（含缓存写入价）；再加 `max_tokens` 乘以最高的输出单价。`max_tokens` 现在是 `models.yaml` 的必填项。
- **账本**：迁移 `00003_budget.sql` 重建了 `budget_entries`（M1 的占位表从没写过数据）。每次网络请求一条 RESERVE，之后恰好由一条 SETTLE 或 RELEASE 关闭，两个部分唯一索引保证这一点；EXTEND 按 `(run, 幂等键)` 去重。预留在一个 IMMEDIATE 事务里检查“已结算 + 未结算预留 + 本次 ≤ 上限”再写入。
- **网关**：模型调用改成“计数 → 预留 → 记录请求 → 发送 → 结算”。答复和结算在同一个事务里落库。没答复的请求按三种情况关闭：没离开 agentd 的释放；供应商回 429/5xx 的按 0 结算；其余（超时、连接断开）不知道供应商收没收费，按整笔预留结算。预留不够时返回 `budget_exhausted`，工作流停在 PAUSED_BUDGET。
- **崩溃**：agentd 启动时，在接任何请求之前，把还开着的预留按全额结算（reason `open_at_start`）。T1 的“供应商已答复、结果没落账时杀 agentd”现在断言了这一条。
- **追加**：`agentctl budget extend <run-id> --usd 2.50`（`ExtendBudget`，幂等键默认每次新生成）。记下 EXTEND 后直接给工作流发门铃信号；通知 outbox 留到 M4。门铃丢了，暂停的调用最多一小时后也会自己重查。`runs get` 显示已花、已预留和上限。
- **适配器接口**：拆成 `CountTokens` 和 `Call` 两步，`Call` 只发一次网络请求，错误分三类：`ErrNotSent`、`*RejectedError`（429/5xx 可重试，其余不可重试）、其他（结果未知）。

### 我做的取舍（开工前已确认）

- 429/5xx 不在网关里重试，交给 Temporal 的活动重试：每次尝试一个请求、一笔预留。重试节奏由工作流定，所以保护供应商的只能是网关的限流，限流要和 Claude 适配器（M2b）一起上线。
- 结构化输出校验、拒答、缓存统计、限流、循环保护放到 M2b。

### T7 怎么测

一个工作流同时发 50 个模型调用，起始预算只够约 20 笔预留。测试本身发现一个问题：假供应商一次调用约 1 毫秒，前面的调用很快按实际费用结算、腾出余额，后面的就都能预留，50 个全部通过，根本没有争抢。所以测试让每个请求在发出前持有预留 500 毫秒。

- 第一波（前 50 次调用）不注入故障：20 笔预留成功，30 个调用停在 PAUSED_BUDGET。
- 追加 $5 后第二波：按调用次序注入 429、500、答复丢失、请求没发出、按回退模型答复各一次。预算充足，每个故障都必然触发。
- 断言：按写入顺序重放账本，每一条之后都满足“已结算 + 未结算预留 ≤ 上限”；每笔预留恰好关闭一次，结算不超过预留；假供应商自己的记录（测试用自己的单价独立计价）和账本逐个请求对上；50 个调用全部成功，所以没有丢失的唤醒；网络请求数 = 50 + 4 次重试。

一次运行的账本：54 笔预留（每笔约 43,656 micros），50 笔按用量结算共 189,965 micros，2 笔拒绝按 0，1 笔结果未知按整笔，1 笔释放。

### 还没做 / 风险

- `count_tokens` 本身要一次网络请求（免费但限流），M2b 要处理它失败的情况：失败时不预留、不发送，返回可重试错误。
- 结算超过预留说明上限算错了：账本照实记账（会超过上限），并记一条错误日志。真实供应商上线后要盯这条日志。
- 价格表里 Opus 的价格抄自设计文档（2026-10-15 查询），M2b 接真模型前要对官方定价页再核一遍。

## M2b：Claude 适配器（2026-10-17，进行中）

代码部分已完成，用本地模拟的 API 测过。T1 用 Claude 真模型的验收要花钱，等你同意后单独做。

### 做了什么

- **密钥**：`models.yaml` 里写 `key: "keyring:<service>[/<account>]"`，用 zalando/go-keyring 读，在 macOS 上就是调用 `/usr/bin/security`。agentd 启动时就读，读不到直接拒绝启动。条目由 `security` 自己创建、自己读取，agentd 重新编译也不会触发钥匙串弹窗。
- **Anthropic 客户端只认给它的 key**：用 `option.WithoutEnvironmentDefaults()`，不读 `ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、profile、身份联合，也不读 `ANTHROPIC_BASE_URL`。SDK 的自动重试关掉（`WithMaxRetries(0)`）。测试里故意在环境变量里放了一把错的 key 和错的地址，确认都没被用上。
- **计 token**：用 count_tokens 接口，分别对主模型和每个回退模型各数一次，取最大值，因为不同模型的分词器可能不同。
- **请求的组成**：任务的提示词作为系统提示并开缓存；参数里每个 `<name>_ref` 指向的 blob 放进一段带标签的内容，放在最后。标签名带上内容哈希的前缀，内容本身无法提前写出闭合标签、跳出这一段。提示词明确写了：标签里的内容是数据，不是指令。
- **结构化输出**：`output_config.format` 加 JSON Schema（`config/schemas/audit_report.json`）。答复回来后网关再按同一份 schema 校验一次，不合格就再要一次。第二次是一个新请求，单独预留、单独结算。被 `max_tokens` 截断的答复不重试，因为同样的上限再要一次还会被截断。校验通过后，整份输出存成 `report_ref`，`blobs` 里列出的字段（patch）存成 `<field>_ref`，其他字段原样内联。
- **拒答和回退**：`stop_reason: refusal` 映射成 `refused`，并带上 category。服务端回退用列出具体模型的写法（`claude-opus-4-8`），不用 `"default"`，因为上限必须事先知道会用到哪些模型。结算按 `usage.iterations` 的每一次尝试，各按各的模型单价计。
- **错误分类**：HTTP 错误答复记为 `RejectedError`，按 0 结算（408/409/429/5xx 可重试，其余不可重试）；连不上（dial/DNS）算没发出去，释放预留；超时、连接中途断开结果未知，按整笔预留结算。
- **价格表**：加了 Opus 4.8（$5 / 缓存写入 5 分钟 $6.25、1 小时 $10 / 缓存命中 $0.50 / 输出 $25），是对照官方定价页核对过的。Opus 5.5 原有的价格也核对过，没有问题。
- **限流**：`models.yaml` 的 `requests_per_minute`（Anthropic 设为 20），每个供应商一个令牌桶，突发上限是一分钟配额的四分之一。最多等一分钟，等不到就当没发出去：释放预留，交给 Temporal 重试。
- **循环保护**：新表 `calls` 记录每个逻辑调用，重试共用同一个活动 ID，只算一次。默认每个任务最多 20 次模型调用、100 次网关调用；同一个工具用同样参数最多调 3 次。“同参数”只对工具计：模型调用在预算暂停或审批之后会用同样的参数重发，这是正常流程，不是循环。
- **其他**：网关改为按供应商名找适配器，因为同一种适配器可能接多个供应商、各用各的 key。`model_calls` 加了 `request_seq`（迁移 00004）。开发用的 Claude 配置是 `config/dev/agentd-claude.yaml`。

### 还没做 / 要注意

- **T1 用 Claude 真模型的验收**：要给测试框架加一个真模型模式。现有的 T1 断言依赖假模型的行为，比如一定会给出补丁、会写假供应商自己的日志。估计花费不到 1 美元，跑之前先问你。
- `max_tokens` 先设 16000，不流式。Opus 5.5 的思考也算在输出 token 里，如果经常被截断，就改成流式并调大，预留也会跟着变大。
- 安全审计任务可能碰到网络安全类拒答。Opus 5.5 允许“在源码里找漏洞”，提示词也要求不写利用代码；误拒时回退到 Opus 4.8。

### 推送前的安全审查（2026-10-17）

这次在推送之前就做了安全审查，没有像 M1 那样推完才查。审查没有发现 key 外泄的路径：日志、错误信息、账本、请求和答复记录里都没有。它报了 6 个问题，下面是核实之后的处理：

1. **回退时预留不够**（中）：一次请求里，主模型可能先输出一段再拒答，回退模型再按自己的 max_tokens 输出，两次都要计费。原来的上限只按“最贵的那一个模型”算，确实可能结算超出预算上限。现在上限改为把每个候选模型各自的上限加起来。代价是开回退后，每笔预留大约翻倍，比如 2 万 token 的 diff 从约 $0.62 变成约 $1.4。**这和设计文档第 9 节“预留按所有候选中最贵的算”不一致，文档要改，改之前先给你看改动清单。**
2. **循环保护能被绕过**（中）：活动 ID 由 Worker 自己选，而且一个活动结束后，它的 ID 可以拿来再用。现在一个逻辑调用由“活动 ID + Temporal 首次调度它的时间”来认。这个时间由服务端填写、重试时不变，所以重用 ID 发起的新调用会被重新计数。另外网关自己限制每个调用最多 10 次尝试，因为重试策略是 Worker 写的。还有一个口子没堵上：参数里多塞一个无关字段，就能绕过“同参数”的计数，要等 M3 给工具加参数 schema 时一起解决；在那之前，总调用数的上限照样有效。
3. **开发流程里 Worker 读得到 key**（中）：Worker 不开沙箱时，它和你是同一个用户，能用 `security` 读出钥匙串里的 key。实测在 srt 沙箱里读不到：带上钥匙串文件路径也找不到，列 `~/Library/Keychains` 会报 Operation not permitted。沙箱探针加了这两项检查；README 里提醒：只要用了真 key，Worker 就必须开沙箱。
4. **blob 可以跨任务读**（中）：模型调用原来会展开参数里任意一个 `sha256:` 引用，Worker 只要从别的任务的历史里看到某个引用，就能让模型读到别的任务的内容。现在每个 blob 记录是哪个任务产生的（迁移 00006），适配器只展开本任务自己的。引用参数的名字必须是小写字母和下划线，同一个 blob 不能用两次。
5. **计 token 不受限流和预算约束**（低）：现在预算连输出那部分都不够时，直接返回预算不足，不再去计 token；加上每个调用最多 10 次尝试，计 token 的次数就有了上限。
6. **key 引用写错时把原值写进日志**（低）：错误信息里不再回显这个值，因为它可能就是一把误填进去的真 key。

审查列的剩余风险里，又改了三处：
- 500/502/504 改为按整笔预留结算，只有 429、529 和其他 4xx 才按 0 结算，因为这几种 5xx 可能是服务端已经算完、在网关层超时；
- 回退时只取最后一个 fallback 块之后的答复；
- `max_tokens` 超过 SDK 的非流式上限时，agentd 启动就报错。之前这种情况会在发请求之前失败，却按整笔预留扣钱，而且每次重试都扣。

**留到后面的：**
- M3 接真工具时，dev policy 里 `open_draft_pr` 不需要审批、也没有 `deny_paths`，有人在 diff 里注入指令，就可能开出一个改 `.github/**` 的 PR。所以 `agentd-claude.yaml` 到时候要换成需要审批的 policy。
- 限流不分任务，一个预算充足的任务能占满每分钟 20 个请求的配额。
- Worker 能从 Temporal 的失败信息里看到 Anthropic 的 request ID 和 workspace ID，这些不是密钥。
- srt 沙箱里，`security` 仍然能列出系统钥匙串（`/Library/Keychains/System.keychain`）的条目属性，比如 Wi-Fi 网络名。读取密码需要管理员授权，你的登录钥匙串也碰不到（探针检查的就是它）。这算一个小的信息泄露，留到 M5 沙箱定稿时，看能不能连 securityd 也一起挡掉。
